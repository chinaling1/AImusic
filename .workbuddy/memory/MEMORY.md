# 项目长期记忆：古韵AI（AI音乐）

## 项目定位

面向专业音乐人的 AI 古风音乐创作工具。四步工作流：提示词优化 → 歌词生成 → 曲谱生成 → MIDI/音频导出。
技术栈：React 19 + TS + Vite（前端）/ FastAPI + music21（后端）/ Electron 打包。

**当前首要目标**：以此项目参加 **2026 第 3 届全国大学生数智链应用大赛 · 人工智能大类 · AI 音乐赛道**。
**作品完成硬线 2026-09-20**（手册第9条，非 10-09）；提交截止 **2026-10-09 24:00**，平台 dabc.org.cn。
评审以**手册修订版**为准：选题定位 10 + AI技术与艺术体现 65 + 技术规范与文档 15 + 展示答辩 10。
完整方案见 `参赛方案-V2-AI音乐赛道.md`；官方依据见 `参考资料/2026参赛手册.pdf`；
往届获奖数据见 `参考资料/2025第2届获奖名单.pdf`。

## 官方硬性事实（手册为准，勿凭官网通知判断）

- **作品须在 2025-10-01 ~ 2026-09-20 内制作完成**，10-09 仅为提交截止。两者不同，别搞混。
- 音频格式 **wav 或 mp3**；演示视频 ≤8 分钟。
- 创作过程说明须含：提示词 + **元标签设计** + 技术路线 + 跨平台设计流程。
- AI 音乐赛道**无需**大赛链平台发布、无需确权；数字音乐赛道两者都需要。
- 官方明确鼓励「**本地部署** + **原创或改进算法**」的音乐生成路线 → 我方 V2 路线属官方认可方向。

## 竞争情报（决定策略，勿忽略）

- 2025 届音乐类获奖 176 件，一等奖仅 10 席，**中传王铉一人占 5 席**，其余来自川音/西音/南艺/浙传。
- **2026 赛道从「区块链+音乐」改为「AI 音乐」，70 分转向技术方法评分** → 对我方（AI 专业）有利。
- **明确主报 AI 音乐赛道，不报数字音乐赛道**（后者考音频工程，非我方强项）。
- 策略：不做高 30 分艺术表达，做高 70 分技术分（自修复算法 + 演奏法算法化 + 干预证据链）。
- 作品命名遵循往届惯例：**2–4 字中文短名**。

## 关键技术决策（勿推翻）

- **不使用端到端音乐生成大模型**。MiniMax 音乐 API 已于 2026-08-20 对新用户关闭，免费 API 全停；开源 MiniMax-Music3 需 24GB 显存，GTX 1650 不可承载。
- 采用 **确定性渲染管线**：LLM 生成符号音乐 → 音乐理论约束校验与自修复 → FluidSynth 本地渲染 → 混音母带。CPU 可跑，可控、可复现、可举证。
- LLM 输出格式用 **ABC 记谱法**（紧凑、LLM 准确率高），内部规范格式用 **MusicXML**（便于出谱与 MuseScore 交互）。
- 音频渲染主路径 FluidSynth；备选 MuseScore 4（Muse Sounds 音色更优）。

## 项目约定

- **git 存档必须做**，且中文不能乱码。仓库已配置：`core.quotepath=false`、`i18n.commitEncoding=UTF-8`、`i18n.logOutputEncoding=UTF-8`。
- 提交信息用中文，写清改了什么。每个改造阶段结束即提交。
- **git 提交历史是参赛原创周期的时间证据**（赛事一票否决项含"非本届周期原创"），有额外价值。
- 源码导出用 `git archive`（自动排除 node_modules），保证源文件包 ≤100M。
- 代码注释使用中文。

## 风险红线

- **素材许可**：赛事一票否决项含"使用非授权素材"。任何 SoundFont / 声库 / IR，许可不明一律不用。逐项记录在《素材许可清单》。
- **意识形态**：作品主题避开宫斗、鬼怪、消极厌世、历史虚无；选传统文化传承/匠心/青春家国方向。
- 演示视频 ≤50M，源文件包 ≤100M，PDF 建议 PDF/A-1b。根文件夹命名 `学校全称-队长姓名-作品名称`。

## 已知缺口（V1 遗留，待按 V2 方案补）

`services/audio_service.py::midi_to_audio` 为空壳不渲染音频；无音乐理论约束层；无人声链路；
单乐器伴奏；无混音母带；歌词无格律校验；无 LLM 自修复重试；无干预证据导出。
