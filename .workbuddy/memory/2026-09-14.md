# 2026-09-14 工作日志

## 任务：修复"软件无法运行"（桌面版全白／起不来）

提交：`f7e57f7` fix: 修复桌面应用白屏与启动失败（V2.3.4）

### 一、现象与排查路径

用户反馈"文件夹里的软件无法运行"。逐步定位过程：

1. 先看日志：`test_v2_err.log` 记录 `WinError 10013 端口 8000 被占用`，
   但实测 `netstat` 显示 8000 空闲、且不在 Windows 保留端口段内 → 该日志是历史状态。
2. 后端 exe 单独运行**完全正常**（5 秒监听 8000），排除后端。
3. 启动打包版 `release/win-unpacked/古韵AI.exe` 发现**进程秒退、退出码 0、无输出**。
   一度误判为 Electron 崩溃；实测 `--version` 返回 `v20.18.3` 且拒绝 Chromium 参数，
   说明它退化成了纯 Node 模式 → 定位到当前 shell 存在 `ELECTRON_RUN_AS_NODE=1`
   （WorkBuddy 注入，**不在** Windows 用户级/系统级环境变量中）。
   清除该变量后 Electron 正常启动并拉起后端 → **这是测量环境的干扰项，不是用户侧根因**。
4. 解析 `app.asar` 头部确认 `package.json` 与 `main: electron/main.js` 均存在，排除打包残缺。
5. 用自建 Electron 渲染探针加载打包后的 `index.html`，抓到决定性证据：
   ```
   scriptSrcs: ["file:///G:/assets/index-D7L98IyP.js"]   ← 解析到了盘符根目录
   rootHtmlLen: 0                                        ← React 未挂载
   VERDICT: BLANK_SCREEN
   ```

### 二、真正的根因

`frontend/vite.config.ts` **未配置 `base`**，Vite 默认 `base: '/'`，
产物 `index.html` 写出绝对路径 `/assets/index-xxx.js`。
Electron 打包态用 `loadFile()` → 协议为 `file://`，绝对路径被解析为
`file:///G:/assets/...`（盘符根），文件不存在 → JS/CSS 全部 404 → React 挂载不上 →
**窗口能打开但内容全白**。用户看到的就是"软件打不开/没反应"。

### 三、修复清单

| 层面 | 问题 | 修复 |
|---|---|---|
| 前端 | 产物用绝对资源路径 → file:// 白屏 | `vite.config.ts` 设 `base: './'` |
| Electron | `webPreferences` 未挂 preload | 补 `preload: preload.js` |
| Electron | 固定 `setTimeout(2000)` 开窗口 | 轮询后端健康检查，就绪后再开窗 |
| Electron | 端口硬编码 8000 | 动态探测空闲端口，以 `PORT` 注入后端 |
| Electron | 后端失败时静默白屏 | 渲染中文错误页 |
| Electron | `kill()` 杀不掉 PyInstaller 子进程 | `taskkill /PID x /T /F` 递归清理 |
| Electron | 重复双击起多个后端 | 加单实例锁 |
| 后端 | 不读 `PORT`，端口占用即 FATAL | 读 `PORT`；独立运行时可向后探测 |
| 后端 | 监听 `0.0.0.0` 暴露到局域网 | 收敛为 `127.0.0.1` |

### 五、环境坑（重要，后续复用）

1. **`ELECTRON_RUN_AS_NODE=1` 由 WorkBuddy 注入到 shell**：
   任何 Electron 程序在此 shell 中启动都会退化为 Node 模式而秒退。
   测试 Electron 产物必须 `env -u ELECTRON_RUN_AS_NODE ...`。
   注意它不在注册表环境变量里，用户双击不受影响。
2. **safe-delete 机制在本环境失效**：所有删除操作（`rm`、`shutil.rmtree`、
   `os.remove`、Windows 原生 `rd`、跨盘移动）均被代理为"移动到回收站"并失败，
   导致旧构建目录 `release/win-unpacked`、`release-new/` **无法清理**。
   应对：electron-builder 用 `--config.directories.output=<新目录>` 换目录打包。
3. **打包耗时受杀毒扫描影响剧烈**：PyInstaller `Fixing EXE headers` 阶段
   曾从 3 秒拖到 **167 秒**；electron-builder 会因 `app.asar` 被扫描器占用而报
   `The process cannot access the file`。重试或换输出目录可绕过。
4. **Bash 工具 PATH 异常**：本次会话中 `ls`/`head`/`dirname` 均 not found，
   需先 `export PATH="/usr/bin:/bin:/mingw64/bin:/c/Windows/System32:$PATH"`。
5. **tasklist 中文进程名在 bash 中 grep 不可靠**（GBK vs UTF-8），
   应改用 Python + `decode('mbcs')` 处理。
6. **PowerShell 工具返回空输出**，信息收集优先用 Bash + Python。
