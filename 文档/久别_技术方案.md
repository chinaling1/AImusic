## 0. 摘要

《久别》的技术方案核心是**两层确定性算法 + 一层概率性算法**的混合架构：

- **确定性算法层**：14 种英文结构标签校验、中文→英文标签映射、字数上限、元标签六项完整性、注记行格式、字符计数与 Unicode 折算——所有规则**不依赖 LLM**，可复现、可审计。
- **概率性算法层**：DeepSeek-Pro 用于提示词优化与歌词生成；MiniMax Audio（Music-3.0）用于成品音频渲染。
- **端到端管线**：浏览器/Electron 前端 → FastAPI 后端 → SQLite 提示词版本库 → 提示词包导出 → MiniMax 网页版 → mp3 候选 → 人工选优。

创新点集中在"**提示词工坊**"这一范式：把端到端大模型抽卡式生成，分解为"用户掌控结构 + 算法保证合规 + 大模型负责渲染"的三方协同。技术评分项"以原创或改进算法为核心"对应这套确定性格式校验器与版本证据链。

class ValidateRequest(BaseModel):
    styles: Optional[str] = ""        # 风格描述（→ MiniMax Styles 输入框）
    meta_tags: Optional[str] = ""     # 六项结构化元标签

class Issue(BaseModel):
    level: str        # error / warning / info
    where: str        # lyrics / styles / meta / system
    message: str      # 人类可读的修复建议


class ValidateResponse(BaseModel):
    ok: bool                          # 是否无 error（warning 不影响 ok）
    issues: List[Issue]               # 按检查顺序排列

### 2.3 算法伪代码

```python
ALLOWED_TAGS = [
    "Intro", "Verse", "Pre-Chorus", "Pre Chorus", "Chorus", "Interlude",
    "Bridge", "Outro", "Post-Chorus", "Post Chorus", "Transition",
    "Break", "Hook", "Build Up", "Build-Up", "Inst", "Solo",
]
CN_TAG_MAP = {
    "主歌": "Verse", "副歌": "Chorus", "前奏": "Intro", "尾奏": "Outro",
    "间奏": "Interlude", "桥段": "Bridge", "导歌": "Pre-Chorus",
    "主歌1": "Verse 1", "副歌1": "Chorus 1",  # ... 共 10+ 条
}
TAG_PATTERN = re.compile(r"^\[([^\]]+)\]\s*$")
NUMBERED_TAG_PATTERN = re.compile(
    r"^(" + "|".join(re.escape(t) for t in ALLOWED_TAGS) + r")\s+\d+$"
)
NOTE_PATTERN = re.compile(r"^[(（].+[)）]\s*$")
META_TAG_NAMES = ["Genre", "BPM", "Key", "Vocals", "Instruments", "Arrangement"]


def _check_tag(tag: str) -> tuple[Optional[str], Optional[str]]:
    """返回 (level, message)；level=None 表示合法。"""
    # 中文检测（含中文 → 给出映射建议）
    if re.search(r"[\u4e00-\u9fff]", tag.strip()):
        suggestion = CN_TAG_MAP.get(tag.strip())
        if suggestion:
            return "error", f"标签 [{tag}] 应改为 [{suggestion}]"
        return "error", f"标签 [{tag}] 含中文"
    # 合法英文标签（含连字符/空格/序号）
    if tag.strip() in ALLOWED_TAGS or NUMBERED_TAG_PATTERN.match(tag.strip()):
        return None, None
    # 大小写不规范（降级为 warning）
    for allowed in ALLOWED_TAGS:
        if tag.strip().lower() == allowed.lower():
            return "warning", f"标签 [{tag}] 大小写不规范"
    return "error", f"标签 [{tag}] 不在 14 种支持标签内"


def validate_prompt(req: ValidateRequest) -> ValidateResponse:
    issues = []
    # ---- Styles ----
    if len(req.styles) > 2000:
        issues.append(Issue("error", "styles", "..."))
    # ---- 元标签完整性 ----
    missing = [n for n in META_TAG_NAMES if f"[{n}]" not in (req.meta_tags or "")]
    if missing:
        issues.append(Issue("warning", "meta", "..."))
    # ---- 歌词逐行解析 ----
    if not req.instrumental:
        tag_lines = []
        for i, line in enumerate(req.lyrics.split("\n")):
            stripped = line.strip()
            if not stripped.startswith("["):
                continue
            m = TAG_PATTERN.match(stripped)
            if m:
                level, err = _check_tag(m.group(1))
                if err:
                    issues.append(Issue(level, "lyrics", f"第 {i+1} 行：{err}"))
                tag_lines.append((i + 1, m.group(1).strip()))
            else:
                issues.append(Issue("error", "lyrics", "标签未独占一行"))
        # 结构顺序检查
        if tag_lines and _normalize(tag_lines[0][1]) not in ("intro", "verse"):
            issues.append(Issue("warning", "lyrics", "开头建议 [Intro] 或 [Verse]"))
        ...
    ok = not any(i.level == "error" for i in issues)
    return ValidateResponse(ok=ok, issues=issues, stats={...})
```

### 2.4 算法特征

| 维度 | 表现 |
|---|---|
| 时间复杂度 | O(n)，n 为歌词总字符数 |
| 空间复杂度 | O(n)，主要用于存储 tag_lines 与 issues |
| 确定性 | 输入相同则输出完全相同（无随机数、无 LLM） |
| 可测性 | 单元测试可枚举全部边界情况（中文标签、超长、嵌套、空字符串、纯音乐） |
| 国际化 | 当前仅中英文混合；CN_TAG_MAP 覆盖 10+ 种中文标签常见错误 |
| 性能 | 实测校验 3500 字符歌词 < 5 ms |

### 2.5 与"以原创或改进算法为核心"的对应

该校验器是本作品"原创算法"的核心体现：

1. **自研规则集**：14 种支持标签与 10+ 条中文→英文映射，是基于 MiniMax 官方文档的二次提炼，非简单翻译。
2. **可解释性**：每条 issue 都有明确的修复建议，用户无需猜测。
3. **零 LLM 依赖**：避免"用 LLM 评判 LLM 输出"的不稳定性，且无调用费用、无延迟。
4. **可移植性**：纯 Python 标准库（`re` + `pydantic`），可独立打包为 CLI 工具。

## 3. 核心算法 ②：歌词生成与确定性净化

**位置**：`backend/app/routers/lyric.py::sanitize_lyrics`（约 15 行）
**性质**：后处理算法，与 LLM 协同的双保险

### 3.1 问题

LLM 输出歌词时，偶发以下两类污染：

1. **markdown 代码围栏**：LLM 习惯用 ` ``` ` 包裹歌词输出
2. **前言**：LLM 偶发"以下是歌词："等非歌词内容

### 3.2 算法

```python
def sanitize_lyrics(raw: str) -> str:
    """
    1. 去除 markdown 代码围栏行
    2. 裁掉第一个结构标签行之前的所有前言
    """
    lines = (raw or "").strip().split("\n")
    # 步骤 1：去围栏
    lines = [ln for ln in lines if not ln.strip().startswith("```")]
    text = "\n".join(lines).strip()
    # 步骤 2：去前言（找到第一个 [ 开头的行，丢弃其之前所有内容）
    for idx, line in enumerate(text.split("\n")):
        if line.strip().startswith("["):
            if idx > 0:
                text = "\n".join(text.split("\n")[idx:])
            break
    return text.strip()
```

### 3.3 双保险策略

| 层级 | 作用 |
|---|---|
| 提示词层（前端） | 在 prompt 中明令"禁止代码围栏、禁止前言"——降低 LLM 输出概率 |
| 后处理层（后端） | 即便 LLM 仍输出污染，`sanitize_lyrics` 做最终净化——确定性兜底 |

实测：4 首《久别》歌词生成中，3 首在 LLM 端已干净，1 首触发 `sanitize_lyrics` 的"去围栏"操作。

async def save_prompt_version(step: str, type: str, content: str,
                              session_id: str, note: str = "") -> int:
    """保存一条版本；返回自增 id"""
    async with aiosqlite.connect(DB_PATH) as db:
        cursor = await db.execute(
            "INSERT INTO prompt_versions (session_id, step, type, content, note, created_at) "
            "VALUES (?, ?, ?, ?, ?, ?)",
            (session_id, step, type, content, note,
             datetime.now(timezone.utc).isoformat())
        )
        await db.commit()
        return cursor.lastrowid


async def get_prompt_versions(session_id: str, step: str = None) -> List[dict]:
    """按时间顺序拉取版本链"""
    async with aiosqlite.connect(DB_PATH) as db:
        if step:
            cursor = await db.execute(
                "SELECT * FROM prompt_versions WHERE session_id=? AND step=? ORDER BY created_at",
                (session_id, step))
        else:
            cursor = await db.execute(
                "SELECT * FROM prompt_versions WHERE session_id=? ORDER BY created_at",
                (session_id,))
        return [dict(row) for row in await cursor.fetchall()]
```

### 4.3 量化干预指标（衍生算法）

```python
def calc_intervention_rate(versions: List[dict]) -> dict:
    """基于版本库计算干预率与平均编辑距离"""
    from Levenshtein import distance as lev
    
    human_count = sum(1 for v in versions if v["type"] == "human_modified")
    total = len(versions)
    
    distances = []
    for i, v in enumerate(versions):
        if v["type"] == "human_modified":
            # 找最近的前一个 ai_optimized 版本
            prev_ai = next((x for x in reversed(versions[:i])
                            if x["type"] == "ai_optimized"), None)
            if prev_ai:
                d = lev(prev_ai["content"], v["content"])
                distances.append(d / max(len(prev_ai["content"]), len(v["content"])))
    
    return {
        "intervention_rate": human_count / total if total else 0,
        "avg_edit_distance": sum(distances) / len(distances) if distances else 0,
        "version_count": total,
        "human_modified_count": human_count,
    }
```

### 7.2 关键 V2.3.4 修复点（实测）

| # | 问题 | 修复 |
|---|---|---|
| 1 | Electron 桌面态**白屏** | `vite.config.ts` 设 `base: './'`，避免 `file:///G:/assets/...` 404 |
| 2 | `loadFile` 资源 404 | 同上 |
| 3 | 固定 `setTimeout(2000)` 让首屏请求失败 | 改为轮询 `/api/` 健康检查，就绪后再 `createWindow` |
| 4 | 端口硬编码 8000 | Electron 主进程动态探测空闲端口 → `PORT` 注入后端 |
| 5 | 后端 `0.0.0.0` 监听暴露到局域网 | 收敛为 `127.0.0.1` |
| 6 | PyInstaller 双进程 `kill()` 失效 | 退出用 `taskkill /PID x /T /F` 递归清理 |
| 7 | 双击起多个后端 | 加单实例锁 |
| 8 | 控制台中文乱码 | 非 tty 时 `reconfigure(encoding='utf-8')` |
| 9 | onefile 下 `__file__` 指向临时目录 | `SECRETS_PATH`/`OUTPUT_DIR` 改用 exe 目录 |
| 10 | asar 内 28 MB 冗余 dist-backend | `files` 移除 `dist-backend/**`，改走 `extraResources` |
| 11 | 安装包体积 | 137 MB → **109 MB** |

## 9. 风险与缓解（技术视角）

| 风险 | 概率 | 影响 | 缓解 |

| 数据丢失 | 低 | 中 | SQLite 单文件易备份；建议每天 `git archive` 导出源码；版本库与源码独立 |
