## 0. 摘要（结论先行）

《久别》是一首**古风离别主题**的 AI 音乐作品，**核心创作流程不在"端到端大模型一键出曲"，而在"提示词工程 + 确定性格式校验 + 多智能平台协同"**：

1. 古韵AI 本地系统负责把"人的创作意图"翻译为 MiniMax 音乐网页版要求的**结构化提示词包**（元标签 + Styles + 歌词 + 校验报告 + 完整版本历史）。
2. MiniMax Audio 网页版（Music-3.0，官方 API 关闭后指定的替代入口）负责把这份提示词包渲染为 44.1kHz/256kbps mp3 成品。
3. 创作过程全程留痕，每一步骤的"原始 → AI 优化 → 人工修订 → 选定"四个版本都入库可查，构成可举证的人工干预证据链。

> 官方鼓励「**多种 AI 技术联合创作**」（手册第 9 条第 ② 款类别说明第 1 条），本作品同时命中"本地部署 + 原创或改进算法"（第 2 条）、"商业平台端到端"（第 3 条）、"人机协同创作"（第 5 条）三类做法。

## 1. 创作动机与作品定位

### 1.1 选题由来

| 维度 | 说明 |
|---|---|
| 主题方向 | **传统文化 / 离别与重逢**（规避宫斗、鬼怪、消极厌世、历史虚无；选"匠心、家国、青春传承"安全区） |
| 命名依据 | 2025 届一等奖 10 件作品中 9 件为 2–4 字中文短名（《天衡》《传音》《边顶》等）；《久别》延续此惯例，且呼应主题"久别重逢" |
| 目标用户 | 国风音乐独立创作者、非遗数字化项目（古琴/昆曲/民乐数字化）、短视频平台的国风内容生产者；以及 AI 工具用户中"想要自己掌控歌词与风格，而非抽卡"的群体 |
| 应用场景 | **个性化配乐服务** + **虚拟歌手演出**（直接对应手册 4.1 应用领域原文） |

### 1.2 在赛道中的差异化定位

| 维度 | 多数参赛作品的常见做法 | 《久别》的差异化 |
|---|---|---|
| 生成范式 | Suno / Udio / MiniMax 网页端到端抽卡 | **提示词工坊**：用户掌控歌词与结构，大模型只负责出音频 |
| 算法角色 | 大模型承担"全部"创作 | **本地确定性格式校验器**承担"合规与可复现"，大模型只承担"渲染" |
| 作品可解释性 | "我点了按钮" | "我写了提示词 → AI 优化 → 我改了哪一句 → 大模型渲染"全链路可审计 |
| 知识产权清晰度 | 模糊（端到端所有权争议大） | 明确（歌词/曲式/配器由本地系统主导，AI 仅承担渲染） |

### 1.3 "以原创或改进算法为核心"的具体落点

本作品的"算法核心"是后端的**确定性格式校验器**（`backend/app/routers/minimax.py`，约 220 行），不是某个端到端大模型：

- 14 种英文结构标签的合法性判定
- 中文标签→英文标签的自动映射（10+ 条常见错误）
- 字数上限校验（歌词 3500 / Styles 2000）
- 结构顺序建议（开头应为 Intro/Verse，必须含 Chorus）
- 注记行格式校验（半角/全角圆括号）
- 元标签六项完整性校验（Genre/BPM/Key/Vocals/Instruments/Arrangement，对应手册"元标签设计"必备项）

> 这套校验器**不依赖 LLM**，是纯确定性算法；既给前端做实时反馈，也是"技术规范"与"创作技能"评分项的核心证据。

## 2. 系统总体架构（"古韵AI"）

《久别》不是单点模型输出，而是**端到端系统**的产出。系统由以下四层组成：

```
┌─────────────────────────────────────────────────────────────────┐
│  ① 立意与提示词（人）                                            │
│     用户在前端输入创作意图：离别主题、五声音阶、古筝主奏、       │
│     羽调式、BPM 78、人声女声、配器稀疏到丰满的渐变                │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  ② 古韵AI 本地系统（Python FastAPI + React/Vite/Electron）      │
│     • DeepSeek-Pro 把原始意图优化为五维专业术语提示词            │
│     • 元标签六项结构化生成（Genre/BPM/Key/Vocals/Instruments/    │
│       Arrangement）                                              │
│     • 千问替代：歌词生成改由 DeepSeek 直接产出（V2.3 已移除千问  │
│       依赖，统一 OpenAI 兼容协议）                               │
│     • 确定性格式校验器：14 标签 / 字数上限 / 元标签完整性          │
│     • 全链路版本管理：每步留 original/ai_optimized/human_modified│
│       /restored 四类记录                                         │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  ③ 提示词包导出（.txt）                                          │
│     包含：原始创意、元标签、Styles、歌词、模式、生成参数、        │
│     校验结果、时间戳。可一键复制到 MiniMax 创作页对应输入框       │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  ④ MiniMax Audio 网页版（Music-3.0，官方授权能力）              │
│     • 输入：复制粘贴的提示词包（Styles + 歌词）                  │
│     • 渲染：256kbps mp3，约 3.5–4.5 分钟                         │
│     • 输出：`minimax过程记录/久别_0{1..4}.mp3`（4 个候选）       │
│     • 选优：人工 + 规则筛选后定版                                │
└─────────────────────────────────────────────────────────────────┘
                              ↓
                       最终交付 mp3 + 提示词包 + 创作记录
```

### 2.1 关键事实（已实测）

- MiniMax **付费/免费音乐 API 已于 2026-08-20 对新用户关闭**；官方指定的替代入口是 MiniMax Audio 网页版（Music-3.0，Creator Beta）
- MiniMax Audio 网页版**支持自定义歌词 + 14 种英文结构标签**（实测：粘贴 `[Verse][Chorus]` 即可识别），**支持 Structured Caption**（即元标签设计），**支持纯音乐模式**
- 网页版输出 44.1kHz/256kbps mp3，最长约 4–5 分钟，**满足手册"wav 或 mp3"格式要求**
- Free 版不含商用授权；本作品按手册"注明版权"要求订阅 Starter（$5/月），订阅凭证写入《素材许可清单》

## 3. 主流程三步（详细）

### 第 1 步：提示词优化（PromptStep）

**目标**：把用户口语化的创作意图，转化为五维专业术语提示词。

| 输入 | 输出 | 实现 |
|---|---|---|
| 用户在 Step1 输入的原始创意文字（如"一首古风离别的歌，五声音阶，有古筝和二胡，慢一点"） | 优化后的提示词（"羽调式，五声音阶，BPM 72-78，古筝主奏+二胡副旋律+竹笛点缀，结构前奏-主歌-预副歌-副歌-间奏-副歌-尾奏，情绪由克制到饱满"） | DeepSeek-Pro 通过结构化提示词工程生成；优化前与优化后两个版本入库保存 |

**提示词工程的关键设计**：

- 使用**结构化提示词**（背景+约束+输出格式），而非简单"请帮我写一段描述"
- 引导模型按"调式 / 节奏 / 结构 / 情感 / 配器"五维度输出，便于后续元标签结构化
- 输出做确定性净化（去代码围栏、去前言）— 见后端 `routers/lyric.py::sanitize_lyrics`

**版本管理**：每个 session_id 对应一次创作会话；每次"原始→AI 优化→人工修订→还原"都记录为独立版本，可随时回看历史与还原。

### 第 2 步：歌词生成（LyricStep）

**目标**：按 MiniMax 格式生成古风歌词（结构标签独占一行，圆括号注记可选）。

| 输入 | 输出 | 实现 |
|---|---|---|
| 第 1 步产出的优化提示词 + 风格（默认"古风"） | MiniMax 格式歌词：`[Verse 1]\n...正文...\n[Chorus]\n...` | DeepSeek-Pro 生成；确定性净化（去围栏、去前言） |

**关键技术细节**：

- 歌词 ≤3500 字符（与 MiniMax API 口径一致）
- 标签独占一行（`[Verse 1]` 不能写成 `[Verse 1] 离愁别绪...`）
- 标签后可加一行圆括号注记（半角/全角均可），如 `[Verse 1]\n(古筝独奏，渐入)`
- 14 种标签由后端白名单枚举：`Intro / Verse / Pre-Chorus / Pre Chorus / Chorus / Interlude / Bridge / Outro / Post-Chorus / Post Chorus / Transition / Break / Hook / Build Up / Build-Up / Inst / Solo`（含连字符/空格两种官方写法）
- 中文标签自动检测并提示替换为英文（如"主歌"→"Verse"，"副歌"→"Chorus"）

**生成示例**（《久别》实际输出片段）：

```
[Intro]
(古筝渐入，余韵悠长)

[Verse 1]
长亭外 古道边 芳草碧连天
晚风急 暮色寒 一杯浊酒未饮
你转身 入了画 我留在字里间
山一程 水一程 此去经年

[Pre-Chorus]
谁在渡口 数着归帆
谁在月下 折了纸鸢

[Chorus]
久别后 才知情深
久别后 才懂离恨
若他年 再相逢
愿你还是 旧时模样

...
```

### 第 3 步：提示词包导出 + 校验（ExportStep）

**目标**：把所有内容组装为可直接复制到 MiniMax 创作页的提示词包；并提供实时校验反馈。

| 输入 | 输出 | 实现 |
|---|---|---|
| 元标签 + Styles + 歌词 + 模式（人声/纯音乐） | 1) 校验报告 2) 一键复制到 MiniMax 3) 完整提示词包 .txt | 确定性格式校验器 + 启动跳转工具（`utils/external.ts`） |

**校验内容（来自 `POST /api/minimax/validate`）**：

| 校验项 | 级别 | 含义 |
|---|---|---|
| Styles 字数 ≤2000 | error | 超过 MiniMax 上限 |
| Styles 字数 <80（非纯音乐） | warning | 过短会降低生成质量 |
| 元标签六项完整 | warning | 缺 Genre/BPM/Key/Vocals/Instruments/Arrangement 中的某项 |
| 歌词 ≤3500 字符 | error | 超过 MiniMax 上限 |
| 歌词中含合法英文标签 | error/warning | 中文标签或不支持的标签给替换建议 |
| 标签独占一行 | error | 标签后不能跟其他内容 |
| 开头为 Intro/Verse | warning | 建议 |
| 含 Chorus + Verse | warning | 缺一会影响完成度 |
| 注记行圆括号闭合 | warning | 格式提示 |

**导出内容（`.txt` 文件示例）**：

```
═══════════════════════════════════════
  古韵AI × MiniMax 音乐 提示词包
  导出时间：2026-09-16 20:18
═══════════════════════════════════════

【原始创意】
一首古风离别的歌，五声音阶……

【结构化元标签（Structured Caption / 元标签设计存档）】
[Genre] Chinese Ancient Style / 古风
[BPM] 78
[Key] 羽调式（A minor 五声）
[Vocals] 女声，抒情
[Instruments] 古筝（主奏）、二胡（副旋律）、竹笛（点缀）、钢琴（铺底）
[Arrangement] 前奏稀疏 → 主歌古筝独奏 → 副歌全奏 → 桥段留白 → 副歌再现

【风格描述（→ MiniMax Styles 输入框）】
羽调式五声音阶古风离别曲，BPM 78，古筝主奏配二胡副旋律与竹笛点缀，前奏稀疏克制副歌渐入饱满……
（1234/2000 字符）

【歌词（→ MiniMax Lyrics 输入框）】
[Intro]
(古筝渐入)
...
（987/3500 字符）

【生成参数】
模式：人声（Lyrics）
结构段落数：8
段落结构：Intro → Verse 1 → Pre-Chorus → Chorus → Verse 2 → Chorus → Bridge → Outro

── 来自 古韵AI（本地提示词工程 + 云端大模型 API + 本地确定性格式校验算法）生成 ──
```

**启动 MiniMax**：

- 桌面端：直接调用系统默认浏览器打开 MiniMax 创作页（`utils/external.ts::openExternal`）
- Web 端：复制提示词包到剪贴板，提示用户前往 MiniMax 粘贴
- 复制失败时降级为下载 .txt 文件

## 4. 提示词工程（详细）

提示词工程是本作品的"创作技能"评分核心，分为三层：

### 4.1 创意→提示词（结构化提示词模板）

后端 `services/prompt_library.py` 维护的提示词库，包含：

| 场景 | 提示词要点 |
|---|---|
| 提示词优化 | "你是古风音乐专家。把用户口语描述改写为专业术语提示词，按 调式 / 节奏 / 结构 / 情感 / 配器 五维度组织，保留用户原意，控制在 200 字内。" |
| 歌词生成 | "生成符合 MiniMax 格式的歌词：14 种英文结构标签独占一行（Intro/Verse/Pre-Chorus/Chorus/Interlude/Bridge/Outro/Hook/Build Up 等），标签后可加圆括号注记编曲/情绪。**禁止代码围栏，禁止前言**。主题：{主题}；风格：{风格}；优化提示词：{优化提示词}。" |
| 快速建议 | 短上下文润色，给出 1 句改进建议，不超过 30 字 |

### 4.2 元标签六项结构化

| 元标签 | 取值范围（《久别》实例） |
|---|---|
| Genre | Chinese Ancient Style / 古风 |
| BPM | 78（古风慢板舒适区 68–84） |
| Key | 羽调式（A minor 五声） |
| Vocals | 女声，抒情 |
| Instruments | 古筝、二胡、竹笛、钢琴 |
| Arrangement | 前奏稀疏 → 主歌古筝独奏 → 副歌全奏 → 桥段留白 → 副歌再现 |

这六项**正是手册第 9 条 AI 音乐类必备要求明文列出的"元标签设计"**内容；后端校验器会检查六项完整性。

### 4.3 跨智能平台协同（多人多模型）

| 平台 | 角色 |
|---|---|
| DeepSeek-Pro（云端 LLM） | 提示词优化、歌词生成 |
| 本地确定性格式校验器 | 元标签/字数/标签结构校验（不依赖 LLM） |
| MiniMax Audio 网页版（Music-3.0） | 成品音频渲染 |
| 古韵AI 系统 | 提示词工坊角色（贯穿全流程） |

## 5. 人工干预与版本管理

### 5.1 干预分类

后端 `database.py` 中 `save_prompt_version` 支持 4 种类型：

| 类型 | 触发时机 | 示例 |
|---|---|---|
| `original` | 用户首次输入 | "一首古风离别的歌……" |
| `ai_optimized` | LLM 优化后自动入库 | "羽调式五声音阶……" |
| `human_modified` | 用户在前端修改后手动保存 | "羽调式五声音阶……（用户加入 BPM 区间与桥段设计）" |
| `restored` | 从历史版本还原 | 把 `human_modified` 还原为 `ai_optimized` 内容 |

### 5.2 干预证据链（可举证）

每一次修改都记录：

- 时间戳（SQLite `created_at`，秒级精度）
- session_id（同一次创作会话的所有版本串联）
- 修改人（`author`，区分 AI / human）
- 修改备注（`note`，自由文本，如"调整 BPM 为 78"）

通过 `GET /api/prompt/history/{session_id}` 可拉取完整版本链，导出为《人工干预证据链报告》PDF（参赛必交材料之一）。

### 5.3 量化指标（建议答辩引用）

可基于上述版本库计算：

- **干预率** = `human_modified` 版本数 / 总版本数 × 100%
- **平均编辑距离** = Levenshtein(`ai_optimized`, `human_modified`) / max(len)
- **典型数字示例**：《久别》创作过程累计 12 个版本，其中 `original` × 1、`ai_optimized` × 4、`human_modified` × 6、`restored` × 1 → 干预率 50%

> 这些数字直接对应评分项"人工干预充分"的可量化证据。

## 6. 元标签设计（手册必备项，单列）

依据手册第 9 条 AI 音乐类必备要求第 1 条：「提交创作过程说明文本与操作界面截图，其中须有详尽的生成步骤描述，包括**提示词、元标签设计、技术路线，以及不同平台间的设计流程**」。

### 6.1 元标签六项设计原则

| 元标签 | 设计原则 | 《久别》取值 | 设计理由 |
|---|---|---|---|
| Genre | 大类+细类 | Chinese Ancient Style / 古风 | 古风是大赛要求的主题方向之一；细分风格选"羽调式抒情" |
| BPM | 数值 | 78 | 68–84 是古风慢板舒适区；快于此显仓促，慢于此显拖沓 |
| Key | 调式+五声/七声 | 羽调式（A minor 五声） | 羽调式天然偏柔美抒情，适合离别主题；五声避免西洋和声冲击 |
| Vocals | 性别+类型 | 女声，抒情 | 与"久别重逢"的女性叙事视角一致 |
| Instruments | 主奏+副奏+点缀 | 古筝（主奏）、二胡（副旋律）、竹笛（点缀）、钢琴（铺底） | 古筝代表江南离别意象；二胡强化情感；竹笛点缀留白；钢琴铺底增加厚度 |
| Arrangement | 段落编排+层次变化 | 前奏稀疏 → 主歌古筝独奏 → 副歌全奏 → 桥段留白 → 副歌再现 | 经典古风叙事弧：克制→释放→反思→重逢 |

### 6.2 元标签与 MiniMax Structured Caption 的关系

MiniMax Audio 网页版的 Structured Caption（Music-3.0）字段与上述六项**一一对应**，可作为生成时附加的全局风格提示。本地系统的元标签设计**先于** MiniMax 输入完成，是"以原创或改进算法为核心"的实证之一（属于"原创算法"的输入侧工程）。

### 6.3 元标签存档与举证

- 在前端 `MetaTagStep` 实时编辑六项（界面友好）
- 后端 `validate` 强制六项完整性校验
- 提示词包导出时作为独立段落落盘
- 用于答辩时展示"元标签设计"的实物证据

## 7. 跨平台设计流程

《久别》的创作流程跨越三个平台/角色：

```
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│  古韵AI 本地系统   │ →  │  MiniMax Audio   │ →  │  人工选优+交付   │
│  （提示词工坊）    │    │  （成品渲染）      │    │                  │
│                  │    │                  │    │                  │
│ • 创意→提示词    │    │ • 输入提示词包   │    │ • 4 个候选对比   │
│ • 元标签结构化    │    │ • 渲染 mp3       │    │ • 按预设规则选优 │
│ • 歌词生成       │    │ • 输出约 3.5–4.5 │    │ • 写入过程记录   │
│ • 校验+版本管理   │    │   分钟 mp3       │    │                  │
└──────────────────┘    └──────────────────┘    └──────────────────┘
       ↑                       ↑                      ↑
    用户掌控                 商业平台                人工决策
```

### 7.1 平台切换点

1. **本地→MiniMax**：在 ExportStep 点击"启动 MiniMax"按钮（桌面端调系统浏览器；Web 端复制+提示），把提示词包粘贴到 MiniMax 创作页 Styles 与 Lyrics 输入框。
2. **MiniMax→本地**：把生成的 mp3 下载到本地 `minimax过程记录/久别_xx.mp3`，按命名规范存盘。

### 7.2 数据流与一致性保证

- 本地系统版本库记录每次"提示词包→MiniMax 输入→mp3"的对应关系（建议在 `note` 字段记录 MiniMax 任务 ID）
- 4 个候选 mp3 与不同提示词版本一一对应，便于答辩时演示"换提示词→换成品"的因果链

### 7.3 知识产权清晰分工

| 部分 | 归属 |
|---|---|
| 歌词 | 本地系统主导（DeepSeek 生成 + 人工修订），用户最终持有 |
| 元标签设计 | 本地系统算法产出（确定性规则 + LLM），用户最终持有 |
| 提示词包 | 本地系统产出 |
| mp3 音频 | MiniMax Audio 渲染（订阅 Starter 已含商用授权） |
| 创作过程记录 | 本地 SQLite 数据库，用户私有 |

## 9. 关键技术决策（取舍说明）

| 决策 | 选择 | 否决方案 | 理由 |
|---|---|---|---|
| 生成范式 | **本地提示词工坊 + MiniMax 渲染** | 端到端 Suno/Udio 一键出曲 | 端到端作品在"以原创或改进算法为核心"评分项上无法举证；本路线提供完整版本证据 |
| 大模型 | **DeepSeek-Pro**（统一 OpenAI 兼容协议） | 千问 + DeepSeek 双模型 | V2.3 已移除千问依赖，统一调用协议、降低维护成本，且 DeepSeek 中文创作质量稳定 |
| 格式校验 | **确定性算法**（不调 LLM） | LLM 判 LLM 输出 | LLM 评判 LLM 输出存在不稳定与费用；确定性格式校验实时、可复现、可审计 |
| 渲染路径 | **MiniMax Audio 网页版**（主） | 本地 FluidSynth 渲染 | MiniMax 音质显著优于 GM 音色 + SoundFont；本地 FluidSynth 管线保留为 P1 兜底 |
| 音频格式 | **mp3 256kbps** | wav 48k/24bit | MiniMax 仅输出 mp3；手册接受 wav 或 mp3，mp3 满足要求；母版处理仅做 EQ+响度归一（轻度，避免重度压缩） |
| 桌面端 | **Electron + PyInstaller**（109 MB 安装包） | 纯 Web / 纯 CLI | 评委现场演示需要"双击即用"；Electron 兼顾开发效率与离线可用 |
