> 重构目标：在**不改变功能与外部行为**的前提下，提高代码可读性与启动速度。
> 重构日期：2026-09-09　|　范围：backend（本轮已完成）+ frontend（进行中）
> 原则：接口路径、请求/响应字段、UI 交互与文案一律不变；只做结构整理、重复消除、依赖瘦身、启动路径优化。

### 2.3 行为微调说明（3 处，均为修复既有缺陷，且对外契约不变）

1. **`call_deepseek_flash` 的 `max_tokens` 256 → 2048**：原值会把「快速润色」的返回内容截断在 256 token，属于明显缺陷。响应结构不变。
2. **歌词生成按模式区分指令**：纯音乐模式追加「只输出结构标签与注记、不输出唱词、≤400 字符」，演唱模式追加「押韵硬约束 + 禁止项清单」。解决了原实现中「纯音乐模式仍要求押韵工整的中文正文」的语义冲突。
3. **输出约束强化**：提示词优化与歌词生成的 prompt 均新增「禁止 ``` 围栏、禁止前后缀解释、分隔标记严格写法」条款，降低 LLM 输出污染风险。

### 2.4 启动速度优化结果

| 措施 | 效果 |
|---|---|
| `music21` 延迟导入 | 启动路径移除该重型依赖（单独导入 0.91 s）。实测「全量导入 2.16 s ≈ 仅主流程路由 2.17 s」，说明兜底管线已不再拖累启动 |
| 删除 `lrc_utils` | 可忽略 |

> **诚实结论**：后端可优化空间已接近耗尽。剩余约 2 s 是 Python 解释器 + FastAPI/uvicorn/openai 的固定开销，与本项目代码无关。若需进一步提速，只能更换技术栈或改打包方式（如 PyInstaller 预编译），不建议在参赛周期内做。

### 3.4 store 整理（`musicStore.ts`）

- `version: 1` + `migrate`：自动清理旧 localStorage 中的兜底字段，避免历史数据污染

- `sessionId`：初始状态即生成 UUID，`onRehydrateStorage` 兜底回灌（修复"sessionId 恒空"缺陷）
- 状态与 setter 按链路分组注释（全局 / 提示词 / 歌词）

### 3.5 美观化与一致性

- 计数显示统一（同超限配色逻辑），中文字体栈保持 `"Microsoft YaHei", "PingFang SC"`

## 六、重要事实纠正

**「本地 LLM」表述不准确，须停止使用。**

本项目的真实技术构成是：

- **本地**：提示词工程、确定性格式校验算法、交互与证据链
- **云端 API**：DeepSeek V4（`deepseek-v4-pro` / `deepseek-v4-flash`）负责元标签与歌词生成；Qwen 仅用于兜底曲谱管线
- **成品音频**：MiniMax 音乐网页版生成

任何参赛材料不得声称「本地部署大模型 / 本地推理」。正确表述：**本地部署的确定性算法（格式校验器）+ 云端大模型 API 生成 + 人机协同干预**。此点由合规审核列为 P0，答辩被追问即失分。
