## 0. 摘要（结论先行）

《久别04》的技术方案核心是**「本地提示词工程 + 确定性格式校验 + 三类版本入库」**的混合架构：

- **本地系统（古韵AI V2.3）**：负责把用户的创作意图结构化为可直接粘贴到 MiniMax Audio 网页版的提示词包（`Meta + Styles + Lyrics`），并通过 14 种结构标签校验 / 字数上限 / 元标签六项完整性 / 注记行格式四项确定性规则实时校验输出。
- **外部云端**：DeepSeek Pro（提示词优化 + 歌词生成）+ DeepSeek Flash（快速润色）。
- **终端成品**：用户在 MiniMax Audio 网页版（Music-3.0）粘贴提示词包后人工生成 mp3，本系统不直接调用 MiniMax API。

**与同赛道其他作品的边界**：本作品专注于「提示词工程的可审计性」，**不涉及音频渲染、不含自动修订循环、不含音乐理论项校验、不含 ABC 曲谱生成**（这些是规划中的 V3 工作）。

## 2. 核心算法：结构化提示词生成

### 2.1 三段式输出约束

`backend/app/prompts/prompt_library.py::OPTIMIZE_PROMPT` 强制 LLM 输出严格两段：

```
===META===
[Genre] ...
[BPM] ...
[Key] ...
[Vocals] ...
[Instruments] ...
[Arrangement] ...

===STYLES===
（80-200 字连贯中文，禁换行/项目符号）
```

**约定**：
- 分隔行严格 `===META===` 与 `===STYLES===`，不加空格、不改大小写
- META 段只能 6 行 `[标签] 值`，不得有空行、序号或解释
- STYLES 必须为单行纯文本
- 第一个字符必须是 `===META===`，其后不得有任何前言、`\`\`\`` 代码围栏

### 2.2 歌词生成 prompt（`LYRICS_PROMPT`）

- 标签必须英文方括号且独占一行（14 种受支持标签）
- 标签后下一行可加中文圆括号注记（编曲 / 人声 / 情绪）
- 推荐结构：`[Intro] → [Verse 1] → [Pre-Chorus] → [Chorus] → ... → [Outro]`
- 全文 ≤1500 字符（API 上限 3500 留余量）
- 押韵硬约束：副歌四句须同韵且句式字数一致
- 纯音乐模式追加 `LYRICS_INSTRUMENTAL_EXTRA`：只输出结构标签与圆括号注记

### 2.3 输出净化（`backend/app/routers/lyric.py::sanitize_lyrics`）

防 LLM 输出污染的双保险（提示词已禁止 + 兜底正则裁剪）：
1. 去除 markdown 代码围栏行
2. 找到第一个 `[` 开头的结构标签行，丢弃其之前的前言

## 3. 核心算法：本地确定性格式校验

`backend/app/routers/minimax.py` 是本作品的**核心算法资产**（按手册"以原创或改进算法为核心"评分项）。完整算法为：

### 3.1 14 种英文结构标签

```
Intro, Verse, Pre-Chorus, Pre Chorus, Chorus, Interlude,
Bridge, Outro, Post-Chorus, Post Chorus, Transition,
Break, Hook, Build Up, Build-Up, Inst, Solo
```

（官方 14 种，含连字符/空格两种官方写法，共 17 条正则）

### 3.2 中文→英文标签自动映射

10+ 条常见错误，自动给出替换建议：

| 中文 | 英文建议 |
|---|---|
| 主歌 | Verse |
| 副歌 | Chorus |
| 前奏 | Intro |
| 尾奏 | Outro |
| 间奏 | Interlude |
| 桥段 | Bridge |
| 导歌 | Pre-Chorus |
| 主歌1 | Verse 1 |
| 主歌2 | Verse 2 |
| 副歌1 | Chorus 1 |
| 主歌一 | Verse 1 |
| 主歌二 | Verse 2 |

### 3.3 字数上限与阈值

- `Styles` 风格描述：上限 2000 字符（API 口径）
- `Lyrics` 歌词：上限 3500 字符
- `Styles` 过短：< 80 字符触发 warning（API 建议 80-200 字）

### 3.4 注记行格式

标签下一行允许圆括号注记（半角 `(...)` 或全角 `（...）` 均可），不闭合则触发 warning。

### 3.5 结构顺序检查

- 开头应为 `[Intro]` 或 `[Verse 1]`，否则 warning
- 缺少 `[Chorus]` 则 warning
- 仅有 `[Chorus]` 但无 `[Verse]` 则 warning（叙事不完整）

### 3.6 元标签六项完整性

```
[Genre] [BPM] [Key] [Vocals] [Instruments] [Arrangement]
```

任一缺失触发 warning，warning 等级不阻断 `ok` 标志位。

### 3.7 输出响应

```json
{
  "ok": true|false,
  "issues": [{ "level": "error|warning|info", "where": "lyrics|styles|meta", "message": "..." }],
  "stats": {
    "styles_chars": 123,
    "styles_limit": 2000,
    "lyrics_chars": 1234,
    "lyrics_limit": 3500,
    "sections": ["Verse 1", "Chorus", ...],
    "section_count": 6
  }
}
```

`ok` 由 `error` 是否存在决定；warning 与 info 不影响。

## 4. 核心算法：三类版本入库

`backend/app/database.py` 维护一张 `prompt_versions` 表：

| 字段 | 类型 | 含义 |
|---|---|---|
| id | INTEGER PK | 主键 |
| step | TEXT NOT NULL | `prompt` / `score` |
| type | TEXT NOT NULL | `original` / `ai_optimized` / `human_modified` |
| content | TEXT NOT NULL | 完整文本内容 |
| timestamp | DATETIME | 默认 `CURRENT_TIMESTAMP` |
| parent_version_id | INTEGER | 父版本（预留字段，前端未启用） |
| note | TEXT | 用户备注 |
| session_id | TEXT NOT NULL | 会话标识（前端自动生成 UUID） |

**三种类型分别对应**：
- `original`：用户首次输入（`/prompt/optimize` 自动入库）
- `ai_optimized`：LLM 返回结果（`/prompt/optimize` 入库）
- `human_modified`：用户编辑后保存（`/prompt/history/save` 入库）

**注意**：schemas.py 中曾定义 `restored` 类型作为预留字段，**当前版本未启用恢复操作**（前端 `PromptHistoryDrawer` 中显示为"回溯"标签但无对应 API）。此为规划中的 V3 工作。

## 5. 健壮性与错误处理

| 场景 | 处理 |
|---|---|
| 网络 / 鉴权 / 限流 / 服务端错误 | `_chat()` 统一捕获转 `LLMServiceError`，路由层 502 友好提示 |
| `finish_reason == "length"` | 显式报错"AI 输出因长度限制被截断"，避免半截歌词静默入库 |
| LLM 输出含 ``` 围栏或前言 | `sanitize_lyrics` 兜底裁剪 |
| 超长 styles / lyrics | 校验器 error 级阻断 |
| 用户直接输入未配 API Key | `lifespan` 中 `llm_service.update_keys` 接受空值，前端 `SettingsModal` 提示 |
| Electron 端口被占 | `findFreePort()` 动态探测，主进程 forward 失败时显式错误页 |

## 7. 边界与不做的事

为保持文档一致性，明确以下范围**不属于**本作品当前实现：

| 不做 | 备注 |
|---|---|
| 音频渲染（MIDI / FluidSynth / 母带） | 本系统不调用 MiniMax API；mp3 需在网页版手动生成 |
| 自动修订循环（生成→校验→再生成） | 校验不过时需用户调整原始 prompt 重试 |
| 音乐理论项校验（五声性 / 调式 / 音域） | 当前校验器只查格式层；音乐层是规划中 |
| 民乐演奏法算法化（刮奏 / 滑音 / 轮指） | 规划中 |
| ABC 曲谱生成与 MIDI 渲染 | 兜底管线已就绪（`/score`, `/midi`），主流程未启用 |
| 平仄格律校验 | 规划中 |
| 证据链一键导出 | 当前仅支持单条版本导出，未打包整段历史 |

这些功能在产品规划中（参见 `07_过程记录/久别04_技术方案.md` 的 V3 路线图），但**当前代码未实现**。

## 8. 安全考虑

- **API Key**：仅通过环境变量或本地 `.secrets.json`（gitignore 覆盖）传入
- **CORS**：仅放行 `http://localhost:5173`、`http://127.0.0.1:5173`、`file://` 的 `null` Origin
- **后端只监听 127.0.0.1**：不暴露到局域网
- **外链限制**：preload `openExternal` 仅放行 `http/https`，挡掉自定义协议注入
- **密钥状态接口**：只返回 `deepseek_configured` 布尔，不返回 key 明文
