## 二、字符计数口径详解

### 2.1 官方上限来源

MiniMax 音乐生成 API 文档（`platform.minimaxi.com` / `intl.minimaxi.com`，Music-3.0 口径）：

- `lyrics`（歌词）：**1 – 3500 字符**（非纯音乐模式必填；纯音乐模式可留空）
- `prompt`（风格描述，对应网页版 Styles 输入框）：**0 – 2000 字符**

网页版与 API 共用同一模型（Music-3.0），按官方文档口径取同一上限。本项目将 3500 / 2000 作为唯一事实来源，后端常量与前端常量各持一份（见 §六-3 改进建议）。

### 2.2 换行与空白

- **换行计入字符数**：歌词为多行文本，`\n` 是 MiniMax 歌词格式的组成部分（标签独占一行依赖换行），因此前后端均按"包含换行的完整字符串"计数。
- 空行与首尾空白不做裁剪，与 MiniMax 实际接收内容保持一致。

### 2.3 计数单位差异（前端 JS vs 后端 Python）

| 端 | API | 语义 | 差异场景 |
|---|---|---|---|
| 前端 | `str.length` | UTF-16 码元（code unit） | emoji（如 🎵 占 2 个码元）、部分生僻字（CJK 扩展 B 区占 2 个码元）会被**多计** |
| 后端 | `len(str)` | Unicode 码点（code point） | 每个字符计 1 |

**影响**：当歌词包含 emoji 或扩展区生僻字时，前端显示的字符数 ≥ 后端校验数（最多差一倍）。因歌词正文以常用汉字为主，实际偏差通常为 0；但口径不一致是潜在缺陷，修复建议见 §六-2。

**统一方案**（建议）：前端改用 `[...str].length`（按码点展开），与后端 `len()` 对齐；或两端统一按 UTF-16 码元计数并以 MiniMax 实际计数为准（官方未公开说明，建议留 10% 余量）。

## 三、上限阈值表

| 阈值 | 数值 | 来源 | 性质 |
|---|---|---|---|
| 歌词上限 | 3500 | MiniMax 官方 API 文档 | 官方硬限制（超出无法提交） |
| Styles 上限 | 2000 | MiniMax 官方 API 文档 | 官方硬限制 |
| Styles 过短提示 | < 20 字符 | 项目自定 | 本地质量提示（`warning`，不阻断） |
| 歌词推荐长度 | ≤ 1500 | 项目自定（LLM 提示词约束） | 软约束：为 3500 上限留出余量 |
| 纯音乐模式注记长度 | ≤ 400 | 项目自定（LLM 提示词约束） | 软约束 |

> 注意：`minimax.py` 中「过短」判定阈值（20 字符）与提示文案（"建议 80-200 字"）不一致，属已知问题（§六-4）。

## 四、段落与标签统计规则

### 4.1 结构标签判定

- 逐行扫描，命中正则 `^\[([^\]]+)\]\s*$`（即：整行只有一对英文方括号包裹的标签名）判定为结构标签行。
- **标签必须独占一行**：形如 `[Chorus] 歌词同行` 的写法会被判 `error`（提示"结构标签必须独占一行"）。
- 带序号标签（如 `[Verse 1]`）按 `^(Verse|Chorus|...)\s+\d+$` 放行。

### 4.2 白名单（17 条，覆盖官方 14 种）

`Intro, Verse, Pre-Chorus, Pre Chorus, Chorus, Interlude, Bridge, Outro, Post-Chorus, Post Chorus, Transition, Break, Hook, Build Up, Build-Up, Inst, Solo`

- 中文标签（如 `[主歌]`）→ `error`，并给出映射建议（`主歌→Verse`、`副歌→Chorus` 等内置映射表）。
- 大小写不规范（如 `[chorus]`）→ 给出规范化建议。

### 4.3 注记行（圆括号行）

- 形如 `(古筝泛音渐入)` 的注记行**不计入段落统计**，仅参与格式检查（未闭合圆括号 → `warning`）。
- 已知限制：仅识别半角括号 `()`，全角 `（）` 暂不识别（§六-5）。

### 4.4 结构顺序检查（warning 级，不阻断）

- 首个标签建议为 `[Intro]` / `[Verse 1]`
- 非纯音乐模式建议包含 `[Chorus]` 与 `[Verse]`
- 以上检查基于标签名子串/精确匹配，存在已知漏报场景（见 §六-6）。

## 五、导出包中的统计字段

`ExportStep.tsx` 导出的 `.txt` 提示词包包含：原始创意、结构化元标签、风格描述（含 `N/2000` 标注）、歌词（含 `N/3500` 标注）、生成模式（Lyrics / Instrumental）、结构段落数与段落链（如 `Intro → Verse 1 → Chorus → Outro`）。校验结论（`ok` / issues 列表）在导出页实时展示，导出包记录 `段落结构` 一行。

## 六、已知问题与改进建议

| # | 问题 | 级别 | 修复建议 |
|---|---|---|---|
| 1 | 歌词 / Styles 超限时前端仅标红计数，**未禁用**「确认歌词」「导出提示词包」按钮，仍可导出违规内容 | P1 | `disabled={overLimit}` + 悬浮提示 |
| 2 | 前端 UTF-16 码元 vs 后端码点，计数单位不一致 | P2 | 前端统一改 `[...str].length` |
| 3 | 上限常量在前端 `constants/limits.ts` 与后端 `minimax.py` 各持一份，存在漂移风险 | P2 | 后端 `format-spec` 已暴露官方口径，前端可在应用启动时拉取覆盖本地常量（`api.getMiniMaxFormatSpec` 已就绪但未被消费） |
| 4 | Styles「过短」判定阈值 20 与文案"建议 80-200 字"不一致 | P2 | 阈值改为 80 |
| 5 | 注记行仅识别半角括号，全角 `（）` 既不识别也不提示 | P2 | `NOTE_PATTERN` 兼容全角括号 |
| 6 | 结构顺序检查用子串匹配，`pre-chorus` 含 `chorus` 子串导致漏报；带序号标签（`[Chorus 1]`）未参与统计 | P2 | 统一先归一化（去序号、小写）再判断 |
| 7 | 纯音乐模式下若歌词框仍有内容，逐行标签校验照常执行，可能报出与「歌词应留空」提示相矛盾的错误 | P2 | `instrumental=true` 时跳过歌词标签校验 |
| 8 | 元标签六项完整性（Genre/BPM/Key/Vocals/Instruments/Arrangement）未做校验，`meta_tags` 传给后端但未被消费 | P2 | 校验器增加六项缺失检查（warning 级） |
