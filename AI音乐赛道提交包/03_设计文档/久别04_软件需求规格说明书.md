## 1. 项目概述

### 1.1 背景

随着人工智能技术在音乐创作领域的广泛应用，专业音乐人对 AI 辅助创作工具的需求日益增长。当前市面上的 AI 音乐工具多为端到端"一键生成"模式，缺少面向专业音乐人的精细控制能力，尤其在古风音乐这一细分领域，缺少能够兼顾专业性与创作效率的工具。专业音乐人需要一种能够精确控制创作过程、支持人工干预修改、并产出可直接喂给商用 AI 音乐平台的结构化提示词的工具。

### 1.2 目标

本项目旨在开发一款面向专业音乐人的 AI 古风音乐创作辅助工具——"古韵AI"，实现以下核心目标：

1. **三步闭环工作流**：提示词优化 → 歌词生成 → 格式校验与交付，每步均支持 AI 辅助与人工修改的闭环协作
2. **结构化提示词产出**：以 Meta + Styles + Lyrics 三段式结构生成可直接粘贴到 MiniMax Audio 网页版的提示词包
3. **确定性格式校验**：本地算法实时校验输出是否符合 MiniMax 格式规范（14 标签 / 字数 / 注记 / 元标签六项）
4. **全链路版本可审计**：所有步骤的提示词变化均入库（original / ai_optimized / human_modified 三类），支持按 session 查询

### 1.3 范围

**包含范围**：
- 三步创作工作流的完整实现
- DeepSeek Pro / Flash 双调用（统一 OpenAI 兼容协议）
- 提示词版本历史管理（3 类）
- 确定性格式校验（4 项规则）
- 提示词包一键复制与 MiniMax 网页版打开
- Windows 可执行文件打包
- 古风主题用户界面

**不包含范围**：
- 多用户账户系统和权限管理
- 在线协作功能
- ABC 曲谱生成与 MIDI 渲染（P1 兜底管线保留，主流程不启用）
- 音频渲染与混音
- 自动修订循环（生成→校验→反馈→再生成）
- 音乐理论项校验（五声性、调式、音域、节奏）
- 民乐演奏法算法化
- 平仄格律校验
- 移动端适配
- macOS/Linux 版本

## 2. 功能需求

### 2.1 三步核心模块

| 模块 | 名称 | 描述 |
|---|---|---|
| M1 | 提示词优化模块 | 用户输入 → DeepSeek Pro 优化 → 输出 Meta + Styles |
| M2 | 歌词生成模块 | DeepSeek Pro 生成含 14 种结构标签的古风歌词 |
| M3 | 格式校验与交付模块 | 本地确定性校验 + 一键复制提示词包 + 打开 MiniMax 网页版 |

> 原 V2.3 之前的 M3（曲谱生成）、M4（MIDI 导出）已移出主流程，归入 P1 兜底管线。`legacy/` 目录保留旧组件源码以备恢复。

### 2.2 M1 — 提示词优化模块

#### 功能需求

| 需求编号 | 需求名称 | 优先级 | 描述 |
|---|---|---|---|
| FR-1.1 | 提示词输入 | 高 | 系统应提供文本输入框，最大长度 2000 字符 |
| FR-1.2 | AI 优化提示词 | 高 | 系统应提供"AI 优化"按钮，调用 DeepSeek Pro，强制输出 `===META===` 与 `===STYLES===` 两段 |
| FR-1.3 | 优化结果展示与编辑 | 高 | 系统应展示 AI 优化后的提示词，并允许编辑 |
| FR-1.4 | 快速润色 | 中 | 系统应提供"快速润色"按钮，调用 DeepSeek Flash（max_tokens=200），输出 ≤50 字 |
| FR-1.5 | 确认提示词 | 高 | 系统应提供"确认提示词"按钮，锁定最终版本 |

#### 业务规则

- BR-1.1：AI 优化输出第一字符必须是 `===META===`，其后无前言、`\`\`\`` 围栏
- BR-1.2：`===META===` 段只能 6 行 `[标签] 值`，不得有空行
- BR-1.3：`===STYLES===` 必须为单行纯文本（80-200 字），禁止换行与项目符号

### 2.3 M2 — 歌词生成模块

#### 功能需求

| 需求编号 | 需求名称 | 优先级 | 描述 |
|---|---|---|---|
| FR-2.1 | 提示词参考展示 | 高 | 系统应在歌词生成页面以只读方式展示 STEP 1 确认的最终提示词 |
| FR-2.2 | 歌词参数配置 | 中 | 系统应支持古风风格与押韵偏好设置（前端拼装为 style 字段） |
| FR-2.3 | AI 生成歌词 | 高 | 系统应提供"生成歌词"按钮，调用 DeepSeek Pro，输出含 14 种结构标签的古风歌词（≤1500 字符） |
| FR-2.4 | 歌词编辑 | 高 | 系统应支持歌词文本编辑 |
| FR-2.5 | 输出净化 | 高 | 后端 `sanitize_lyrics` 必须去除 markdown 代码围栏与前言 |
| FR-2.6 | 歌词微调建议 | 中 | 用户编辑歌词时，可调用 `quick_suggest` 获取 ≤50 字建议 |
| FR-2.7 | 歌词导出 | 高 | 系统应提供"保存歌词"按钮，将编辑后的歌词导出为纯文本下载 |

#### 业务规则

- BR-2.1：歌词结构标签必须英文方括号且独占一行（14 种受支持标签）
- BR-2.2：歌词推荐结构 `Intro → Verse 1 → Pre-Chorus → Chorus → ... → Outro`
- BR-2.3：纯音乐模式下歌词留空，仅输出结构标签与圆括号注记（≤400 字符）
- BR-2.4：押韵硬约束：副歌四句同韵，句式字数一致

### 2.4 M3 — 格式校验与交付模块

#### 功能需求

| 需求编号 | 需求名称 | 优先级 | 描述 |
|---|---|---|---|
| FR-3.1 | 实时校验 | 高 | 用户编辑后实时触发 `POST /api/minimax/validate`，返回 issues + stats |
| FR-3.2 | 校验结果可视化 | 高 | ValidationPanel 按 level (error / warning / info) 分色展示 |
| FR-3.3 | 一键复制 | 高 | 按钮把 Meta + Styles + Lyrics 合并的"提示词包"复制到剪贴板 |
| FR-3.4 | 一键打开 | 高 | 调用 `window.electronAPI.openExternal` 打开 MiniMax Audio 网页版 |

#### 业务规则（4 项确定性校验规则）

- BR-3.1：**14 种英文结构标签**合法性判定（详见 §7）
- BR-3.2：**字数上限**（Styles ≤2000、Lyrics ≤3500）
- BR-3.3：**注记行格式**（半角/全角圆括号均可，不闭合则 warning）
- BR-3.4：**元标签六项**完整性（Genre/BPM/Key/Vocals/Instruments/Arrangement，任一缺失则 warning）
- BR-3.5：额外：**结构顺序**（开头 Intro/Verse；必含 Chorus）、**中英映射**（12 条常见中文标签自动建议替换）

### 2.5 M4 — 提示词版本管理模块

| 需求编号 | 需求名称 | 优先级 | 描述 |
|---|---|---|---|
| FR-4.1 | 版本自动记录 | 高 | 用户首次输入（original）、AI 返回（ai_optimized）、用户修改保存（human_modified）时自动入库 |
| FR-4.2 | 历史面板 | 高 | 抽屉式 UI 按时间倒序列出所有版本 |
| FR-4.3 | 版本类型标识 | 高 | 三种类型分别用蓝/紫/绿色标签 |
| FR-4.4 | 版本内容查看 | 高 | 点击版本条目展开完整内容 |
| FR-4.5 | 历史查询 API | 高 | `GET /api/prompt/history/{session_id}` 按 session 返回全部历史 |
| FR-4.6 | 历史保存 API | 高 | `POST /api/prompt/history/save` 保存人工修订版本 |
| FR-4.7 | 历史导出 | 中 | 单条版本内容可复制（未提供一键打包下载） |

> **注**：原 V2.3 主版本中预留的 `restored` 类型与"版本恢复"功能未实现（前端"回溯"标签无对应 API），归入规划中的 V3 工作。

#### 版本数据模型（实际）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | INTEGER PK | 是 | 主键 |
| step | TEXT | 是 | `prompt` / `score` |
| type | TEXT | 是 | `original` / `ai_optimized` / `human_modified`（**3 类**） |
| content | TEXT | 是 | 完整文本内容 |
| timestamp | DATETIME | 是 | 默认 `CURRENT_TIMESTAMP` |
| parent_version_id | INTEGER | 否 | 预留字段，前端未启用 |
| note | TEXT | 否 | 用户备注 |
| session_id | TEXT | 是 | 会话标识（前端 UUID） |

- BR-5.2：所有 AI 调用均使用 OpenAI 兼容 API 格式

## 8. 验收标准

- 三步流程可走通：原始 prompt 输入 → DeepSeek 优化 → DeepSeek 生成歌词 → 校验通过 → 一键复制 + 打开 MiniMax
- 校验器 4 项规则覆盖全部 issue 等级
- 三类版本全部入库，可按 session 查询
- 密钥不外泄；状态接口只返回布尔
- 跨平台（Win）Electron 打包可启动

## 9. 项目约束条件

- 仅支持 Windows 10/11（electron-builder 仅配置 NSIS / win target）
- 依赖 DeepSeek V4 系列 API Key（用户自备）
- MiniMax Audio 网页版需用户登录账号
- Python ≥ 3.10，Node.js ≥ 18

## 11. 明确不做的事（边界清单）

为保持代码与文档一致性，明确以下范围**不属于**本作品当前实现（V2.3-revised）：

| 不做 | 备注 | 状态 |
|---|---|---|
| 音频渲染（MIDI / FluidSynth / 母带） | 本系统不调用 MiniMax API；mp3 需在网页版手动生成 | 永久（设计边界） |
| 自动修订循环（生成→校验→反馈→再生成） | 校验不过时需用户调整原始 prompt 重试 | 规划中（V3） |
| 音乐理论项校验（五声性 / 调式 / 音域） | 当前校验器只查格式层；音乐层是规划中 | 规划中（V3） |
| 民乐演奏法算法化（刮奏 / 滑音 / 轮指） | 规划中 | 规划中（V3） |
| ABC 曲谱生成与 MIDI 渲染 | 兜底管线已就绪（`/score`, `/midi`），主流程未启用 | 规划中（V4） |
