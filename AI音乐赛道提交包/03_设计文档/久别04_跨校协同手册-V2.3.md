## 3. 协作流程（模板：可扩展为团队）

### 3.1 Git 协作约定

- 主分支：`main`，受保护，仅通过 PR 合并
- 功能分支：`feat/<模块>` / `fix/<bug-id>` / `docs/<主题>`
- 提交规范：`feat:` / `fix:` / `docs:` / `refactor:` / `test:` 前缀
- 代码评审：每个 PR 至少 1 名团队成员 approve

### 3.2 文档同步约定

- 代码变更同步更新 `SRS.md`、`技术方案.md`
- API 变更同步更新 `frontend/src/services/api.ts` 与 `backend/app/models/schemas.py`
- 文档版本号与代码版本号同步

## 4. 关键技术决策（与代码一致）

### 4.1 产品定位

**「MiniMax 提示词工坊」**——三步（提示词 → 歌词 → 校验）产出可直接粘贴到 MiniMax Audio 网页版的结构化提示词包。**不集成 MiniMax API、不渲染音频**。

### 4.2 AI 模型选型

- DeepSeek Pro（deepseek-v4-pro）：提示词优化、歌词生成
- DeepSeek Flash（deepseek-v4-flash）：快速润色、短输出
- 千问：**已移除**（V2.3 起统一走 DeepSeek）

### 4.3 版本管理

3 类（`original` / `ai_optimized` / `human_modified`）入库；`restored` 类型**预留字段未启用**。

### 4.4 边界清单

明确**不做**的事（与代码一致）：
- 音频渲染
- 自动修订循环
- 音乐理论项校验
- 民乐演奏法算法化
- ABC 曲谱生成与 MIDI 渲染（主流程）
- 平仄格律校验

详见 `03_设计文档/久别04_软件需求规格说明书.md` §11。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 单人开发能力上限 | 明确边界（不渲染音频、不做音乐理论项），聚焦核心三步链路 |
| LLM API 限额 | 提示词优化 + 歌词生成走 Pro；其他短任务走 Flash；用户自备 Key |
| DeepSeek 模型名变更 | 配置文件 `DEEPSEEK_PRO_MODEL` / `DEEPSEEK_FLASH_MODEL` 可独立调整 |
| MiniMax 网页版变更 | `constants/limits.ts::MINIMAX_MUSIC_URL` 与 `format-spec` 接口集中维护 |
