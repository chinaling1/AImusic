## 0. 摘要

《久别04》是一首古风离别主题的 AI 音乐作品。**核心创作流程不在"端到端大模型一键出曲"，而在"本地提示词工程 + 确定性格式校验 + MiniMax 网页版人工渲染"**：

1. 古韵AI 本地系统把"人的创作意图"翻译为 MiniMax 音乐网页版要求的结构化提示词包（元标签 + Styles + 歌词）。
2. 本地校验器按 14 种英文结构标签 / 字数 / 注记格式 / 元标签六项 四项确定性规则实时反馈合规性。
3. DeepSeek Pro 生成候选提示词 + 歌词，用户做最终选择与微调。
4. 用户在 MiniMax Audio 网页版粘贴提示词包，生成 44.1kHz/256kbps mp3 成品。

**关键边界**：本系统**不调用 MiniMax API，不渲染音频，不含自动修订循环，不做音乐理论项校验**。成品音频的最终生成依赖用户在网页版的人工操作。

## 1. 创作动机与作品定位

### 1.1 选题由来

| 维度 | 说明 |
|---|---|
| 主题方向 | 传统文化 / 离别与重逢（规避宫斗、鬼怪、消极厌世、历史虚无；选"匠心、家国、青春传承"安全区） |
| 命名依据 | "久别04"二字呼应主题"久别04重逢"，延续 2025 届一等奖作品的 2-4 字中文短名惯例 |
| 目标用户 | 国风音乐独立创作者、非遗数字化项目（古琴/昆曲/民乐数字化）、短视频平台的国风内容生产者；以及 AI 工具用户中"想要自己掌控歌词与风格，而非抽卡"的群体 |
| 应用场景 | 个性化配乐服务 + 虚拟歌手演出（直接对应手册"应用领域"原文） |

### 1.2 与同赛道其他作品的边界

| 维度 | 多数参赛作品的常见做法 | 《久别04》的做法 |
|---|---|---|
| 生成范式 | 端到端抽卡式生成 (Suno / Udio / MiniMax) | 提示词工程：用户掌控结构与歌词，DeepSeek 不直接生成音频 |
| 算法角色 | 大模型承担"全部"创作 | **本地确定性格式校验器**承担"格式合规与可复现"，DeepSeek 承担"文本生成" |
| 作品可解释性 | "我点了按钮" | "我写了原始提示词 → AI 优化 → 我改了哪一句 → 校验器反馈 → 最终选定"全链路可审计 |
| 知识产权清晰度 | 模糊（端到端所有权争议大） | 明确（歌词/曲式/配器由本地系统与用户主导，DeepSeek 仅承担文本生成，MiniMax 仅承担音频渲染） |

### 1.3 「以原创或改进算法为核心」的具体落点

本作品的"算法核心"是后端的**确定性格式校验器**（`backend/app/routers/minimax.py`，约 220 行）：

- 14 种英文结构标签的合法性判定
- 中文标签→英文标签的自动映射（12 条常见错误）
- 字数上限校验（歌词 3500 / Styles 2000）
- 结构顺序建议（开头应为 Intro/Verse，必须含 Chorus）
- 注记行格式校验（半角/全角圆括号）
- 元标签六项完整性校验（Genre/BPM/Key/Vocals/Instruments/Arrangement）

> 这套校验器**不依赖 LLM**，是纯确定性算法；既给前端做实时反馈，也是"技术规范"与"创作技能"评分项的核心证据。

## 2. 系统总体架构（"古韵AI"）

《久别04》不是单点模型输出，而是**端到端系统**的产出。系统分为四层（详见 `03_设计文档/久别04_技术方案.md` §1）：

1. **终端层**：React 19 + Vite 8 + Tailwind 4 + Electron 33；古风 UI，三步工作流引导。
2. **后端服务层**：FastAPI REST；提示词优化 / 歌词生成 / 格式校验 / 密钥管理；统一 OpenAI 兼容协议调 DeepSeek。
3. **数据层**：SQLite 持久化三类版本记录；`.secrets.json` 本地持久化设置面板输入的 API Key。
4. **MiniMax Audio 网页版**：用户人工粘贴提示词包后生成 mp3；本系统不集成其接口。

## 3. 创作过程时间线（实际发生）

### 3.1 三步工作流

| 步骤 | 任务 | 实际产物 |
|---|---|---|
| **STEP 1** 提示词优化 | 用户输入原始古风音乐描述；DeepSeek Pro 输出 Meta + Styles | `optimized_prompt` (含 `===META===` 与 `===STYLES===` 分隔行) |
| **STEP 2** 歌词生成 | 用户确认提示词；DeepSeek Pro 输出含 14 种结构标签的古风歌词 | `lyrics` (含 `[Verse 1] [Pre-Chorus] [Chorus] [Outro]` 等标签) |
| **STEP 3** 格式校验 + 复制交付 | 本地确定性校验器按 4 项规则反馈；一键复制提示词包 + 打开 MiniMax 网页版 | 校验 JSON + 用户在网页版生成的 mp3 |

### 3.2 版本入库与可追溯性

每次操作都会在 `prompt_versions` 表中入库一条记录，三种类型：

- `original`：用户首次输入的原始 prompt
- `ai_optimized`：DeepSeek 返回的优化结果
- `human_modified`：用户编辑后保存的版本

> 注：schemas.py 中曾预留 `restored` 类型字段（用于版本回溯），但**当前版本未启用恢复操作**（前端 `PromptHistoryDrawer` 显示"回溯"标签但无对应 API）。这是规划中的 V3 工作。

每条记录带 `session_id`（前端自动生成 UUID），可按会话查询全部历史，构成"人工干预可审计"的证据链。

## 4. AI 工具与生成占比

### 4.1 主要 AI 工具

| 工具 | 版本 | 用途 |
|---|---|---|
| DeepSeek Pro | deepseek-v4-pro | 提示词优化、歌词生成（中文长文本与结构化输出） |
| DeepSeek Flash | deepseek-v4-flash | 快速润色 / 短输出场景 |
| MiniMax Audio | Music 3.0 (网页版) | 成品 mp3 生成（人工操作） |

### 4.2 AI 直接生成占比：约 70%

按创作流程各环节的 AI 直接产出占比：

| 环节 | AI 直接产出 | 人工干预 |
|---|---|---|
| 原始 prompt 输入 | 0% | 100% |
| DeepSeek Pro 提示词优化 | 100% | 0%（结果可被人工编辑） |
| DeepSeek Pro 歌词生成 | 100% | 0%（结果可被人工编辑） |
| 校验与反馈 | 0%（本地确定性算法） | 100%（按反馈决策） |
| MiniMax 网页版音频渲染 | 0%（人工操作） | 100% |
| **整体加权** | **约 70%** | **约 30%** |

即：**AI 直接生成的内容约 70%（提示词优化 + 歌词生成），人工干预约 30%（原始输入、最终选择与微调、网页版音频生成）**。

## 5. 作品特色与创新

### 5.1 三项可证据的创新点

| # | 创新点 | 实现位置 | 可审计证据 |
|---|---|---|---|
| 01 | 提示词三段式结构化 | `backend/app/prompts/prompt_library.py::OPTIMIZE_PROMPT` | 强制 LLM 输出 `===META===` 与 `===STYLES===` 两段；Styles 限 80-200 字 |
| 02 | 本地确定性格式校验 | `backend/app/routers/minimax.py` | 14 标签 / 中英映射 / 字数 / 注记 / 元标签六项 五项规则均可独立函数验证 |
| 03 | 三类版本入库 | `backend/app/database.py` + `prompt_versions` 表 | SQLite 表可按 session 查询全部历史；前端 `PromptHistoryDrawer` 可视化 |

### 5.2 与同赛道其他作品的区别

- **不调用 MiniMax API**：本系统不集成 MiniMax 音频生成 API，所有音频生成由用户在网页版完成。这降低了大模型输出风险，但也意味着 mp3 不在自动化流水线内。
- **不依赖音乐理论项校验**：当前校验器只查格式层（标签/字数/注记/元标签），不查五声性 / 调式 / 音域等音乐层规则。这些是规划中的 V3 工作。
- **不含自动修订循环**：校验不过时需用户调整原始 prompt 后重试，不做"生成→校验→反馈→再生成"的自动闭环。

## 6. 创作总结

### 6.1 收获

- 提示词可结构化复用：三段式输出使 Meta + Styles 与歌词可互相参考，减少重复调试
- 确定性校验可独立作为证据：14 标签 / 中英映射 / 字数上限都是可走全路径的函数，输出报告可作为「设计说明」附件
- 人工干预可查：original / ai_optimized / human_modified 三类记录全部入库，可按 session 查询全部历史
- 提示词包可直接交付：「复制 + 打开 MiniMax 音乐网页版 + 粘贴」三步完成，交付路径明确且可复现

### 6.2 不足与改进方向

- 不涉及音频渲染：成品需用户在 MiniMax 网页版手动生成，未接入平台接口
- 不含音乐理论项校验：当前校验器仅检查格式合规性，不检查音乐理论项
- 调试轮次依赖人工：不含自动修订循环；校验不过时需人工调整原始 prompt 后重新调用
- 证据链导出需升级：当前版本历史仅内存，未提供「提示词包 + 版本历史」一键打包下载

### 6.3 后续计划（V3 路线图）

- 集成 MiniMax Audio API，实现提示词包→mp3 全自动
- 引入音乐理论项校验（五声性、调式一致性、韵脚对齐）
- 加入自修复循环，违规率收敛曲线作为量化指标
- 民乐演奏法算法化（古筝刮奏、二胡滑音、琵琶轮指）
- 平仄格律校验
- 证据链一键导出（PDF/A-1b + SHA-256 绑定）
